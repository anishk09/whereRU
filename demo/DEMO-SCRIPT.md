# WhereRU? — three-minute demo

## Prepare before presenting

1. Run `./start-demo.command` and put all devices on the same Wi-Fi or hotspot.
2. On the hosting Mac, sign in and use **Profile → Reset rehearsal** once. This replaces only the sample demo database and keeps the host signed in as Maya. Sign in Jordan and Alex on the other devices or independent hostnames described in README.md. Enter **000000** for each.
3. In Alex's Home, select **Richard Weeks Hall** and press **Enable nearby alerts**. Open Notifications and **Mark all read** to clear the initial sample alerts, then return Home. Keep this receiving page open.
4. Put Maya and Jordan on Home. Use everyday items. Do not reset or switch accounts during the demonstration. The seven example photos are available inside the upload forms; no external files or API key are needed.

## 0:00–0:55 — lost report and nearby alert

Say: “A student can report an item and ask people near the search area to look, without sharing their exact timeline.”

On **Maya**:

1. Press **I lost something**.
2. Open **Use your example photos** and choose **IMG_3989**, the red bottle. Review the drafted name, color and identifying detail.
3. Continue with **Everyday item**.
4. Choose **Retrace my steps**. Enter **Richard Weeks Hall**, optionally **IDEA3 Lab**, and save the place.
5. Continue. Turn on **Ask nearby helpers to look** and continue to review.
6. Press **Post lost listing**.

Show **Alex's device** receiving **Potential item nearby**. Open the alert to show the broad building search area; the exact lab and identifying printing are absent.

## 0:55–1:40 — found photo and owner notification

Say: “A second student posts a found item. Local image tools draft the details; the matching engine alerts the original owner.”

On **Jordan**:

1. Press **I found something**.
2. Open the example gallery and choose **IMG_3990**, a different photo of the same red bottle. Press **Use this photo**.
3. In **Scan room**, open the example gallery and choose **IMG_3995**. Confirm **Richard Weeks Hall — IDEA3 Lab**, then continue.
4. Review the red bottle details and keep **Hide identifying details from public description** enabled.
5. Press **Notify matching listings**.

Show **Maya's device** receiving **Potential match found**. Open it to show the compatible public description and building, then press **That's mine**.

Explain accurately: the supplied collection has your IDEA3 location label; this is a local example lookup, not a claim that the lab was identified from an official Rutgers panorama. Separate Rutgers classroom comparisons use the installed official reference index.

## 1:40–2:30 — return request and confirmed recovery

1. On **Maya**, press **Send return request**. For this everyday bottle, a message is optional and an owner-only answer is not required.
2. On **Jordan**, open Notifications → **Recovery update**, review the request and press **Approve return request**. Explain that tablets, wallets, keys, IDs and reports marked valuable/sensitive use the private owner-only answer instead.
3. Choose a public meetup location. Optionally send one private message.
4. Jordan presses **I handed it back**. Show that the app waits for the other participant.
5. Maya presses **View return**, then **I received my item**.
6. Show **Found you!**, RETURNED status and the independently awarded 10 finder / 2 owner points.

## 2:30–3:00 — data pool and heatmap

Open **Listings**, choose **Lost**, press **Filters**, and select **Busch** and **Water bottles** to show a shortlist of missing items. Save one report if time permits. Open **Map**, choose **Busch**, and show the real aggregation of the sample reports' shared areas.

Say: “The heatmap uses shared search areas from open lost reports. Sample data is labeled. Exact rooms, photos and private ownership evidence stay protected.”

## Quick recovery during rehearsal

- No match alert: keep Maya's page open, enable notifications in Profile, and confirm that both reports are red bottles in Richard Weeks Hall. A returned item does not generate new open matches; reset before repeating.
- No nearby alert: Alex must enable alerts near Richard Weeks Hall **before** Maya posts, and Maya must enable sharing. Keep the receiving page open.
- Room scan uncertain: use **Choose → Busch → Richard Weeks Hall → IDEA3 Lab → Use this room**. Do not select a guessed classroom.
- Phone cannot reach the server: use the current launcher IP and a shared hotspot if the campus network isolates devices. Keep the host Mac awake and the server running.
- Map background unavailable: online basemap tiles require internet; the shared-area list still shows saved aggregates. Photo lookup, matching, notifications and recovery use the local server.
